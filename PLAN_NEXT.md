## Как разложить по страницам и вкладкам

Сейчас всё на странице идёт одной длинной лентой. С пятью новыми возможностями лента станет нечитаемой, поэтому предлагаю два уровня.

**Боковая навигация** — что изучаем, с группами:

```
Главная

Распределения
  Непрерывные
  Дискретные

Данные
  Подбор закона распределения
```

**Вкладки внутри страницы** — что делаем с выбранным:

| Страница | Вкладки |
| --- | --- |
| Непрерывные, Дискретные | График · Калькулятор · Статистика · Код |
| Подбор закона распределения | Сравнение · Графики · Проверка согласия · Интервалы параметров · Калькулятор · Экспорт |

Боковая панель остаётся для ввода (распределение, параметры, данные), вкладки — для результатов.

Почему дискретные отдельной страницей, а не переключателем: у них другой график (столбики вероятностей вместо кривой плотности), нет `scale`, параметры часто целые, и у них отдельная страница в документации SciPy. Общий код (параметры, выборка, статистика, экспорт) при этом один.

Ограничение вкладок Streamlit: содержимое всех вкладок считается при каждом действии, даже скрытых. Поэтому всё тяжёлое (бутстреп, моделирование для проверки согласия) запускается кнопкой и кэшируется.

## Этапы

Каждый этап — отдельный коммит и пуш после быстрых тестов. Тяжёлые проверки идут в один поток, чтобы не грузить машину.

### Этап 0. Закрыть долг по подбору

1. Независимая проверка математики подбора, в один поток и с ограничением по времени.
2. Исправить найденное.
3. Посмотреть подбор на живом сайте.

### Этап 1. Вкладки и навигация

Разложить существующее по вкладкам и группам навигации. Новых возможностей нет, поведение то же.

### Этап 2. Состояние в ссылке

Распределение и значения параметров записываются в адрес страницы; открытие ссылки восстанавливает тот же график. Кнопка «Скопировать ссылку». Работает для непрерывных и дискретных. Для подбора в ссылку попадают только настройки: загруженные данные в адрес не поместить.

### Этап 3. Калькулятор

Общий модуль, вкладка на всех трёх страницах (в подборе — для выбранного подобранного распределения).

- `P(a < X < b)` с закрашенной областью на графике.
- Квантиль по вероятности и вероятность по значению.
- VaR и Expected Shortfall на уровнях 95%, 99% и произвольном.
- Если величина не определена (у Коши нет среднего, значит нет и ES), так и пишется, без подстановки числа.

### Этап 4. Проверка согласия

- Статистика Андерсона — Дарлинга в общей таблице подбора рядом с Колмогоровым — Смирновым: она чувствительна к хвостам.
- Честное p-значение методом Монте-Карло (`scipy.stats.goodness_of_fit`): параметры переоцениваются на каждой модельной выборке, поэтому оно не завышено. Считается кнопкой для одного выбранного распределения.
- Нынешнее завышенное p-значение KS из таблицы убрать: статистика остаётся, вводящее в заблуждение число уходит.

### Этап 5. Интервалы параметров

- Бутстреп для выбранного распределения: 200 повторных выборок, процентильные 95%-интервалы для каждого параметра и для VaR.
- Пометка вырожденной подгонки: интервал на порядки шире самой оценки или оценка на границе области определения.

### Этап 6. Дискретные распределения

- Страница на общем коде: столбики вероятностей, ступенчатая функция распределения, целочисленные параметры, без `scale`.
- Экспорт скрипта, калькулятор, ссылка.
- Подбор дискретных распределений по данным в этот этап **не входит** (см. вопрос 3).

### Этап 7. Финальная проверка

Полный прогон тестов (около 15 минут процессора, запускаю по твоей отмашке), независимое ревью, проверка на живом сайте, обновление README и скриншота.

## Критерии готовности

- [ ] Бутстреп-интервал накрывает истинный параметр примерно в 95% повторов на модельных данных

## Вопросы

Рядом с каждым моя рекомендация.

1. **Структура.** Группы в навигации и вкладки, как описано выше? *Рекомендую:* да.
2. **Знак риска.** VaR считается для убытка. Что в данных пользователя: доходности (риск в левом хвосте) или убытки (риск в правом)? *Рекомендую:* переключатель, по умолчанию «доходности, риск слева»; VaR и ES показывать положительным числом как размер потери.
3. **Подбор дискретных.** У дискретных распределений SciPy нет готового метода подгонки, нужен отдельный с границами параметров. Делать сейчас? *Рекомендую:* нет, сначала страница; подбор дискретных — следующей задачей.
4. **Бутстреп.** 200 повторов — компромисс между точностью интервала и временем (для `gamma` на 500 наблюдениях секунды, для медленных распределений минуты). *Рекомендую:* 200 по умолчанию, выбор 100/200/500, только по кнопке.
5. **p-значение KS в таблице.** Убрать завышенное и оставить только статистику? *Рекомендую:* да, иначе рядом будут два p-значения с разным смыслом.
6. **Аудитория.** Трейдеры, аналитики, студенты? От этого зависят умолчания: уровни VaR, пример данных (сейчас гамма; для трейдинга логичнее доходности с тяжёлыми хвостами). *Рекомендую:* если трейдинг — пример данных заменить на модельные дневные доходности.

## Что не входит

- Подбор дискретных распределений (вопрос 3).
- Загрузка котировок по тикеру.
- Сравнение нескольких распределений на одном графике в базе.
- Переключатель языка.
